每个经由批处理网格绘制的元素——图片、纹理、精灵、文字、圆角矩形块——都有 `BlendMode`（`EDreamUIBlendMode`）：它的颜色如何与
已经画好的内容合成。**图层组**（`UDreamLayerGroup`，挂在容器上的行为组件）先把整棵子树画进一张单独的纹理，再把这张纹理作为一层
放下：按组自己的混合模式、组自己的不透明度、组自己的遮罩。

## 混合模式

| 分组 | 模式 |
| --- | --- |
| 正常 | `Alpha`（正常）、`Dissolve`（溶解） |
| 变暗 | `Darken`（变暗）、`Multiply`（正片叠底）、`ColorBurn`（颜色加深）、`LinearBurn`（线性加深）、`DarkerColor`（深色） |
| 变亮 | `Lighten`（变亮）、`Screen`（滤色）、`ColorDodge`（颜色减淡）、`Additive`（线性减淡/添加）、`LighterColor`（浅色） |
| 对比 | `Overlay`（叠加）、`SoftLight`（柔光）、`HardLight`（强光）、`VividLight`（亮光）、`LinearLight`（线性光）、`PinLight`（点光）、`HardMix`（实色混合） |
| 反差 | `Difference`（差值）、`Exclusion`（排除）、`Subtract`（减去）、`Divide`（划分） |
| 成分 | `Hue`（色相）、`Saturation`（饱和度）、`Color`（颜色）、`Luminosity`（明度） |

公式取 W3C Compositing and Blending：`Cs' = (1 - Da) * Cs + Da * B(Cb, Cs)`，再按 source-over 合成；W3C 没有定义的模式按图像
编辑器的定义（深色/浅色比较三个通道之和；实色混合在两者之和不小于 1 处为白；溶解按 alpha 的比例随机保留或丢弃像素，图案跟着控件
走）。混合在**编码（sRGB）空间**进行，与图像编辑器一致：视口目标本来就存编码值；线性渲染目标上两种颜色先编码再混合，结果再解码。

### 三种绘制方式

由模式和绘制元素的方式自动决定，不需要设置。

- **混合硬件**——`Alpha`、`Additive`、`Multiply`、`Screen`、`Exclusion`、`Dissolve`。照常合批，部分透明的元素叠在不透明背景上
  结果精确。它们直接混合目标里存的值，所以在线性渲染目标上与图像编辑器略有差别。`Multiply` 在任何 alpha 下都精确：半透明的正片
  叠底只变暗一半（以前会把透明像素涂黑）。
- **读取背后画面的副本**——其余所有模式。这类绘制之前，先把它覆盖到的目标区域拷贝出来，着色器在副本之上混合。同一模式、互不
  重叠的元素共用一次绘制和一次拷贝；重叠的依次绘制，后一个混合在前一个留下的画面上。`Subtract` 和 `LinearBurn` 放在这里而不在
  硬件里，因为部分透明时硬件会把结果截断，公式不会。
- **单元素组**——由材质绘制的元素（自带材质，或内置着色器关闭时的默认材质）用了 `Multiply` 之后新增的任一模式：元素先画进一张
  纹理，再按模式放下。带材质且模式为 `Alpha`、`Additive`、`Multiply` 的元素仍按材质自己的混合方式，与以前一样。

## 图层组

| 属性 | 作用 |
| --- | --- |
| `Isolation` | `PassThrough`（默认：如同没有组）或 `Isolated`（单独绘制）。不透明度、模式或遮罩不是默认值时，无论这里怎么设都单独绘制 |
| `GroupOpacity` | 对合成后的子树整体乘一次：互相重叠的子项一起淡出，不会像各自取控件 `RenderOpacity` 那样互相透出 |
| `GroupBlendMode` | 合成后的子树与背后画面的混合方式，27 种任选 |
| `GroupMask` | 按容器矩形度量的 `FDreamClipMask`，在放下时作用于整张合成结果。不参与点击检测 |

在单独绘制的组里，子项的混合模式只与组内已画的内容混合，不会与组背后的画面混合：隔离组里一个 `Difference` 的白方块会反相它的
兄弟，在空白处就是白色。组内的背景类效果（`UDreamBackgroundBlur` 等后处理元素）读取的是组纹理。组可以嵌套。改组的不透明度、
模式或遮罩只重画合成；在单独绘制和穿透之间切换会让画布重建绘制调用。

### 剪贴到不是图片的下方图层

[剪贴到下方图层](clip-masks.md) 在裁剪里直接跟随图片或圆角矩形块的形状。其它下方图层——文字、平铺或填充的图片、圆环或多边形、
自定义网格、容器（它的子项组成的那一层）、图层组——由 DreamGUI 自动组成一个组：下方图层画进一张纹理并原样放下，剪贴到它的内容
画进第二张纹理，只在第一张有 alpha 的地方放下。剪贴到这类图层的内容按该图层控件的矩形做点击检测。

### 保留框

`UDreamRetainerBox` 的保留纹理也经过同一个合成放下：按它的 `GroupBlendMode`、`GroupRenderOpacity`，以及 `DisplayVisual` 所在
控件的裁剪（包括该控件自己的裁剪遮罩）。设了 `EffectMaterial` 时仍按那个材质绘制，与以前一样。

## 开销与适用范围

- 单独绘制的组需要一张与它在目标上覆盖范围同大的纹理（取自本帧的池，帧画完即归还）、一次清除，以及在该范围上的一次合成；
  读取背后画面的模式另加该范围的一次拷贝。组的边界两侧不合批。
- 读取背后画面的模式，每次绘制拷贝它覆盖的范围，并把所在 pass 拆开。
- 组、读取背后画面的模式与单元素组在**DreamGUI 自己的渲染器绘制的所有画布**上生效：屏幕空间与渲染目标画布、World Space - DreamUI
  Renderer 的世界空间画布，以及设计器和关卡编辑器的预览。世界空间画布上，组纹理经同一视图绘制，与其中元素一样被场景深度遮挡；
  读取背后画面的元素先按深度遮挡、再混合。由引擎渲染器绘制的画布（World Space - UE Renderer）把组当作穿透绘制，把这些模式按 `Alpha`
  绘制，并输出一条指明画布的警告；硬件的六种模式在哪里都有效。有组或这类模式的屏幕空间画布不会按缩小的 `ScreenSpaceRenderScale`
  绘制；组内不做屏幕空间深度测试。世界空间画布上，组会打断该画布与其它画布合并的 pass。
