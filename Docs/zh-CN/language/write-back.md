<a id="what-the-designer-writes-back"></a>

## 设计器写回什么

设计器是该文件的前端：在那里做的改动就是对文本的改动，写进保存该值的那一行——或者写进该节点其他行之后的新行——其余内容逐字节保持原样。有几种东西没有可写入的行，设计器会直接说明（DUI7004），而不是凭空造一行：

- 由 `if` 显示或隐藏的控件的可见性——改条件，或者把该控件移出分支；
- `@fill 2` 上除 Fill 以外的 `SizeRule`——改为在该位置写 `@slot SizeRule = …` 和 `@slot FillWeight = 2`。
  新的权重会替换 `@fill 2` 中的数字，而裸的 `@fill` 被赋予另一条规则时变为 `@slot SizeRule = …`；
- `rows` 表格某一行上除某列的值或该行自身块的某一行之外的任何内容：该行的行只写得下它的列。某列的值会在其单元格中被替换。不能从设计器删除、移动、命名一行或给它加 `+` 块，也不能把节点放在表格旁边（那个位置会在表格内部）——请编辑文本。

节点从其样式的 `+ Component` 行取到的值也不写（DUI7005）：样式是共享的，而节点自身没有 `+` 行来保存这一改动。添加一行（`+ VerticalBox { Spacing = 20 }`），或者改样式。

在设计器中添加的控件会按该文件会用的类型写出：当该类在此处有 `use … as` 别名时使用该别名，对于排布子节点的普通控件则使用容器类型（`VerticalBox Column`）。拖入组件实例某个具名槽位的控件会写进该槽位的填充，`slot Detail { … }`，当实例没有该槽位时会先写出它。在设计器中重命名的无名节点会获得其第一个 id，写在类型之后。`for` 或 `each` 的模板不会被删除或移出它的循环：没有东西可重复的循环无法构建。

一次旋转——通过 2D 视图的旋转手柄、3D 视图的 gizmo 或细节面板完成——会写为欧拉角 `RelativeRotationEuler = (0, 0, 30)`：pitch、yaw 和 roll，单位为度；画布平面内的旋转就是 roll，正值表示顺时针。资产所保存的四元数没有拼写形式，也永远不会被写出。

如果源文件为只读或写入失败，文档会在内存中保留编辑后的文本。之后的 flush 会重试该写入，即使没有任何值发生改变。编译也会重试，并在仍无法写入时报告 DUI6023；当前层级和编辑内容会保留。请签出该文件或解决写入失败问题，然后再次编译。

<a id="from-designer-values-back-to-text"></a>

### 从设计器值回到文本

`FDreamUITextWriteBack` 将设计器编辑转换为 `.dui` 改动。其核心规则是**比较值，而不是源文本的拼写**。`FDreamUITextPatcher` 编辑文本片段；如果把设计器可能碰过的每个属性都交给它，那么只要打印器的格式与作者的写法不同，未改变的值也会被重写。例如，`(400,240)` 和 `(400, 240)` 描述的是同一个值。

因此，一次 flush 会询问：重建当前文本是否会产出实时树所持有的值。它会用编译器自身的 `FDreamUITextBuilder` 从该文本构建第二棵树，然后比较值。它不会为写回另行维护一套对语言的解释。

一次 flush 就是一步撤销，或者在没有变化时不算一步。空操作不会调用 `SetContent`，也不会创建空事务。撤销会把树标记为**在下一个 tick** 重新生成：该通知是在 `FTransaction::Apply` 内部到达的，当时它仍在恢复对象，因此同一事务中的其他控件可能尚未恢复它们的值。

<a id="where-the-text-lives-udreamuidocument"></a>

### 文本住在哪里：`UDreamUIDocument`

对于以文本为后端的控件，文本是唯一真相，设计器是它的图形前端。`UDreamUIDocument`，一个位于 `DreamGUIEditor` 中的 `UCLASS(Transient)` `UObject`，保存一个 `.dui` 文件的完整文本，以便 Unreal 的事务系统能够撤销它。

`UObject` 之所以重要，是因为撤销恢复的是对象。如果文本位于事务之外，Ctrl+Z 可能恢复控件，却在文件中留下新值。随后一次重新编译、重新打开或下一次无关编辑都会从该文件重新生成树，并把本应撤销的改动带回来。

调用方必须遵守三条契约：

1. **调用方拥有事务。** `SetContent` 会调用 `Modify()`，但它自己从不开启事务。它会报告缺少事务，而不是悄悄产生一次不可撤销的编辑。
2. **内存是权威；磁盘可能滞后。** 写入失败时，例如文件只读且尚未签出，会把编辑保留在内存中，报告失败，并在之后的 flush 中重试。
3. **`FlushToDisk` 从不清除只读位。** 通过源代码控制签出该文件，而不是绕过源代码控制系统把它改成可写。

**每个文件只有一个文档，而不是每个编辑器窗口一个**。两个工具包为同一个文件持有各自独立的文档时，会有独立的文本和磁盘哈希：其中一个里的撤销在另一个看来可能像是外部编辑，导致这些窗口不断重新加载并覆盖彼此的状态。

`FDreamUIDocumentRegistry` 通过把规范化后的绝对路径用作键来防止这种情况。注册表持有弱引用；调用方通过 `FDreamUIDocumentHandle` 保留文档，这是一个只可移动、不可复制的有作用域句柄。文档 API 和这一所有权契约声明于
[`Source/DreamGUIEditor/Public/Text/DreamUIDocument.h`](../../../Source/DreamGUIEditor/Public/Text/DreamUIDocument.h)。
